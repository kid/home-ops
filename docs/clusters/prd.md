# prd: kubectl login

Generated by `nix run .#write-docs` from `den.clusters.prd`. Do not edit by hand.

kubectl logs in through Authelia (https://auth.kidibox.net) with [kubelogin](https://github.com/int128/kubelogin),
as in [Authelia's kubelogin page](https://www.authelia.com/integration/openid-connect/clients/kubelogin/).
The Authelia group `admins` gets `cluster-admin`.

## Before you start

- The kubelogin plugin on `PATH`: package `kubelogin-oidc`, binary `kubectl-oidc_login`.
- The 1Password CLI, signed in, with access to the `home-ops-prd` vault.
- SSH access to the node `10.0.40.10`, to fetch the certificate authority of the API server.

## Set up kubectl

```sh
ssh 10.0.40.10 sudo cat /var/lib/rancher/k3s/server/tls/server-ca.crt > /tmp/prd-ca.crt

kubectl config set-cluster prd \
  --server=https://kube.kidibox.net:6443 \
  --certificate-authority=/tmp/prd-ca.crt \
  --embed-certs=true

kubectl config set-credentials prd-oidc \
  --exec-api-version=client.authentication.k8s.io/v1 \
  --exec-interactive-mode=Never \
  --exec-command=kubectl \
  --exec-arg=oidc-login \
  --exec-arg=get-token \
  --exec-arg=--oidc-issuer-url=https://auth.kidibox.net \
  --exec-arg=--oidc-client-id=kube_login \
  --exec-arg=--oidc-client-secret="$(op read 'op://home-ops-prd/authelia/secrets/kubelogin-client-secret')" \
  --exec-arg=--oidc-extra-scope=groups \
  --exec-arg=--oidc-extra-scope=offline_access

kubectl config set-context prd --cluster=prd --user=prd-oidc
kubectl config use-context prd
```

## Check

```sh
kubectl auth whoami
kubectl get nodes
```

The first command opens your browser for Authelia. `whoami` lists the group `admins`.

## Notes

- The client secret is stored in your kubeconfig, as an argument of the plugin.
- If Authelia is down, use the admin kubeconfig on the node: `ssh 10.0.40.10 sudo cat /etc/rancher/k3s/k3s.yaml`.
