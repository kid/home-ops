# prd: kubectl login

Generated by `nix run .#write-docs` from `den.clusters.prd`. Do not edit by hand.

kubectl logs in through Kanidm (https://idm.kidibox.net/oauth2/openid/kube_login) with [kubelogin](https://github.com/int128/kubelogin),
as a public client (PKCE, no client secret). The Kanidm group `admins` gets `cluster-admin`.

## Before you start

- The kubelogin plugin on `PATH`: package `kubelogin-oidc`, binary `kubectl-oidc_login`.
- SSH access to the node `10.0.40.10`, to fetch the certificate authority of the API server.

## Set up kubectl

```sh
ssh 10.0.40.10 sudo cat /var/lib/rancher/k3s/server/tls/server-ca.crt > /tmp/prd-ca.crt

kubectl config set-cluster prd \
  --server=https://kube.kidibox.net:6443 \
  --certificate-authority=/tmp/prd-ca.crt \
  --embed-certs=true

kubectl config set-credentials prd-oidc \
  --exec-api-version=client.authentication.k8s.io/v1 \
  --exec-interactive-mode=Never \
  --exec-command=kubectl \
  --exec-arg=oidc-login \
  --exec-arg=get-token \
  --exec-arg=--oidc-issuer-url=https://idm.kidibox.net/oauth2/openid/kube_login \
  --exec-arg=--oidc-client-id=kube_login \
  --exec-arg=--oidc-extra-scope=groups_name

kubectl config set-context prd --cluster=prd --user=prd-oidc
kubectl config use-context prd
```

## Check

```sh
kubectl auth whoami
kubectl get nodes
```

The first command opens your browser for Kanidm. `whoami` lists the group `admins`.

## Notes

- `groups_name` makes Kanidm put plain group names in the `groups` claim; `groups` would send SPNs
  (`admins@<domain>`), which match no RoleBinding.
- Your username is `https://idm.kidibox.net/oauth2/openid/kube_login#<your Kanidm UUID>`.
- kubelogin caches the refresh token Kanidm issues, so you log in again only when the Kanidm session ends.
- If Kanidm is down, use the admin kubeconfig on the node: `ssh 10.0.40.10 sudo cat /etc/rancher/k3s/k3s.yaml`.
